# MOSS 软件接口协议（v0.1）

本文档是 ESP32-C3 固件与 Windows 电脑端上位机之间的接口契约。
硬件或软件贡献者开始开发前必须先阅读本文档。任何接口变更都需要在 Issue 或 PR 中说明，并同步更新本文档。

## 1. 最小演示目标

项目的最小闭环是：

```text
ESP32 按键
  -> 录制 4 秒 PCM
  -> HTTP 上传电脑端
  -> 电脑端 ASR 识别
  -> DeepSeek 判断普通问答或打开意图
  -> 本地安全校验
  -> 生成 TTS WAV
  -> ESP32 下载并播放
```

P0 必须支持：

- 中文语音识别；
- 普通问题回答；
- 打开预先配置的桌面文件或文件夹；
- 语音回复；
- 网络、ASR、AI 或 TTS 失败时返回可播报的错误提示。

舵机、OLED、唤醒词和持续监听不属于本协议的 P0 范围。

## 2. 双方职责

### ESP32-C3 固件负责人

- 读取按钮并录制固定格式的音频；
- 通过 HTTP 上传原始 PCM；
- 解析电脑端返回的 JSON；
- 下载 `tts_url` 指向的 WAV 并播放；
- 在成功、失败和超时时恢复 LED 状态；
- 不负责 ASR、DeepSeek、桌面路径校验或文件操作。

### Windows 上位机负责人

- 接收并校验 PCM 请求；
- 调用本地 ASR；
- 调用 DeepSeek 或本地关键词兜底；
- 只按照本地白名单打开桌面项目；
- 生成 ESP32 可以播放的标准 PCM WAV；
- 返回固定 JSON，并处理异常和超时；
- 不负责 GPIO、录音时序或功放控制。

## 3. 音频上传接口

### 请求

```http
POST /api/command HTTP/1.1
Host: <电脑局域网 IP>:8765
Content-Type: audio/pcm; rate=16000; channels=1

<原始 PCM 二进制数据>
```

请求体不是 JSON，也不是 WAV 文件，不包含 WAV 文件头。

音频参数固定为：

| 参数 | 约定 |
|---|---|
| 采样率 | 16000 Hz |
| 声道 | 单声道 |
| 采样格式 | 16-bit signed PCM，小端序 |
| 默认录音时长 | 4 秒 |
| 默认请求体大小 | 128000 字节 |

计算方式：`16000 × 4 × 2 = 128000` 字节。软件端不能只依赖固定大小，仍需拒绝空请求和明显过短的录音。

### 成功响应

```http
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8
```

```json
{
  "recognized_text": "打开社团嘉年华",
  "reply": "已打开社团嘉年华",
  "tts_url": "http://192.168.1.100:8765/tts?text=..."
}
```

字段含义：

| 字段 | 类型 | 要求 |
|---|---|---|
| `recognized_text` | string | ASR 识别文本；识别失败时可以为空 |
| `reply` | string | 给用户看的最终回复；应适合直接播报 |
| `tts_url` | string | ESP32 可访问的完整下载地址；无语音时为空字符串 |

`tts_url` 必须使用电脑在局域网中的 IP，不能返回 `localhost`、`127.0.0.1` 或只在电脑本机有效的地址。

### 错误响应

错误响应也应尽量保持固定结构：

```json
{
  "recognized_text": "",
  "reply": "服务暂时不可用，请再试一次。",
  "tts_url": ""
}
```

状态码约定：

| 状态码 | 场景 | ESP32 行为 |
|---|---|---|
| `200` | 成功处理 | 播放 `tts_url`，然后回到待机 |
| `400` | 空录音或录音太短 | 播放/显示错误提示，然后回到待机 |
| `500` | 服务内部错误、ASR 或 TTS 失败 | 播放/显示错误提示，然后回到待机 |
| 请求超时 | Wi-Fi、电脑服务或 AI 超时 | 显示错误状态，不能一直停留在思考状态 |

服务端错误响应不得包含 API Key、完整本地路径、Python 堆栈或其他敏感信息。

## 4. TTS 下载接口

### 请求

```http
GET /tts?text=<URL 编码后的回复文本>
```

### 响应

```http
HTTP/1.1 200 OK
Content-Type: audio/wav
```

返回值必须是标准 PCM WAV，而不是 MP3、AAC 或其他压缩格式。固件已按 RIFF 结构逐块扫描并定位 `fmt ` / `data`，因此：

- 软件端**可以**返回带扩展块（如 `LIST`、`fact`）的 WAV，固件会自动跳过无关块；
- 固件按 WAV 中记录的**实际采样率、声道数、位深**配置 I2S 播放，单声道会自动复制成左右声道，8-bit 会转换为 16-bit，因此 TTS 采样率不必等于 16kHz，也不会出现变调/变速；
- 目前仅支持 **PCM（format tag = 1）**、**8/16-bit**、**1~2 声道**；若要引入 ADPCM、浮点等非 PCM 编码或更多声道，必须同时修改固件和本文档；
- 播放时固件会向串口打印解析参数与写入结果（`[WAV] 解析: …Hz / …声道 / …bit …`、`[WAV] 播放结束: 写入 … 字节 …`），联调时以此核对实际格式。

软件负责人必须在联调时确认实际 TTS 的采样率、声道数、位深和数据块布局；硬件负责人必须用实际返回文件验证播放，并先用固件自带的喇叭自检（开机提示音，或串口发送 `T` 播放 1kHz 测试音）确认功放与喇叭通路本身正常。TTS 格式一旦确定，写入联调记录，不得只凭库的默认值猜测。

## 5. AI 意图和桌面安全边界

DeepSeek 只负责把自然语言理解成两类结果：普通文本回复，或 `open_desktop_item` 工具调用。

工具调用示例：

```json
{
  "name": "open_desktop_item",
  "arguments": {
    "relative_path": "社团嘉年华"
  }
}
```

AI 不得直接决定任意 Windows 路径。上位机必须在本地白名单中再次校验，AI 返回合法格式也不能绕过校验。

白名单示例：

```text
社团嘉年华/
社团嘉年华/项目介绍.pdf
社团嘉年华/接线图.png
```

必须拒绝：

```text
C:\Windows
..\其他目录
\服务器\共享目录
test.exe
test.lnk
删除桌面文件
复制、移动、重命名或写入文件
运行程序或执行系统命令
```

安全实现要求：

- 只允许打开白名单中已存在的文件或文件夹；
- 拒绝绝对路径、UNC 路径、`..`、空字节和命令字符；
- 拒绝可执行文件、脚本文件和快捷方式；
- 禁止删除、修改、移动、复制、重命名、下载、安装和运行程序；
- 执行层只允许使用 `os.startfile()`，禁止 shell、PowerShell、`cmd`、`subprocess` 和 `os.system`；
- 路径校验后仍需确认解析后的目标没有离开桌面目录。

## 6. 服务地址和网络约定

默认服务地址：

```text
http://<电脑局域网 IP>:8765
```

默认端口为 `8765`。ESP32 与电脑必须连接同一局域网，演示前应确认电脑 IP 不会变化，或同步修改固件中的 `SERVER_URL`。

电脑端必须监听局域网地址，而不是只监听 `127.0.0.1`。Windows 防火墙必须允许局域网访问 TCP `8765`。

## 7. 联调顺序

两位负责人必须按以下顺序联调，每一步通过后再进入下一步：

1. 用固定 PCM 请求验证 `/api/command` 能返回 JSON；
2. 用固定 JSON 验证 ESP32 能正确解析三个字段；
3. 用固定 WAV 验证 ESP32 能下载并播放；
4. 接入真实 ESP32 录音，确认 PCM 参数正确；
5. 接入 ASR，确认 `recognized_text` 正确；
6. 接入 DeepSeek 和本地关键词兜底；
7. 验证合法白名单项目可以打开；
8. 验证绝对路径、路径穿越、危险扩展名和危险指令全部被拒绝；
9. 连续运行 30 次并记录失败原因和响应时间。

## 8. 接口验收清单

- [ ] ESP32 上传的是 16kHz、单声道、16-bit 原始 PCM；
- [ ] 请求地址为 `/api/command`，端口为 `8765`；
- [ ] 响应包含 `recognized_text`、`reply`、`tts_url`；
- [ ] `tts_url` 使用电脑局域网 IP，ESP32 可以访问；
- [ ] TTS 返回标准 PCM WAV，实际参数（采样率/声道/位深）已经验证，且与固件串口打印的解析结果一致；
- [ ] 喇叭自检通过（开机提示音或串口发送 `T` 能听到声音）；
- [ ] 服务异常后 ESP32 会恢复待机状态；
- [ ] 普通问题、合法打开指令和非法指令均已测试；
- [ ] 桌面白名单之外的路径无法打开；
- [ ] 未提交 API Key、音频、模型缓存或虚拟环境；
- [ ] 协议变更已同步更新本文档和 README。

## 9. 变更规则

以下内容属于接口变更，必须在 Issue 或 PR 中明确说明：

- URL、端口、HTTP 方法或 Content-Type 变化；
- PCM 采样率、声道、位深或录音时长变化；
- JSON 字段名称、类型或错误码变化；
- TTS 音频格式变化；
- 白名单规则或安全边界变化。

硬件和软件负责人在接口变更后都要完成一次回归联调，不能只修改单方代码。
